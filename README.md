# aitext-check

日本語の文章（主に技術文章）を、ルールベースで校正する textlint の設定一式です。AI が意味を読んで修正するツールではありません。辞書とルールを機械的に適用して、問題のある箇所を指摘します。

## チェックする内容

- **語彙**: 修正すべき語句を検出し、推奨する語句を示します（prh の辞書 `prh-error.yml`）
- **書き方**: 文の長さや句点などを確認します（`ja-technical-writing` のルール）。文書にだけ使います
- **気をつける語句**: 正しい使い方と誤った使い方の両方がある語句を検出し、warning を表示します（`prh-warn.yml`）。チェックは失敗扱いにしません
  - 書き言葉の技術文章に合わない書き方（口語、動詞の名詞化、冗長な言い回し）も、ここで検出し、書き言葉の候補を示します（`じゃない` → `ではない`、`確認を行う` → `確認する`）
  - 「A ではなく B」が 3 回以上ある節も、その節の見出しの行に表示します（`bin/count-dewanaku.mjs`）
  - 体言止めの文（「両方リリース完了。」）が 3 個以上ある節も、その節の見出しの行に表示します（`bin/count-taigen.mjs`）。「こと。」「次のとおり。」と、「。」で終わらない箇条書きの行は対象にしません
  - 7 文以上ある段落も、その段落の最初の行に表示します（`bin/count-paragraph.mjs`）。いくつもの論点を 1 段落に詰めると、読む人は話の変わり目を自分で探すことになるためです。論点ごとに段落を分けます。返答では長い段落が多い（過去の返答で 1,385 個）ので、返答を確認するフックでは止めません
  - 述語の後にコロンを置いて、コードや箇条書きへ続ける書き方（「webhook が以下を自動注入する:」）も表示します。「次のとおり自動注入する。」にします（textlint-rule-preset-ai-writing の `no-ai-colon-continuation`。このプリセットのほかのルールは使いません。理由は `.textlintrc.warn.yml` に書いてあります）
  - 動詞を名詞として使った箇所（「作り損ないを避ける」「引っかかりを出した」）も、形態素解析で検出して表示します（`bin/find-nominal.mjs`）。辞書に書いていない語も検出します
  - 見出しや太字を、動詞の句に名詞を付けた名札にした箇所（「書いた原稿で確かめる問い」「区切りごとに変えるもの」「障害の選び方」）も、形態素解析で検出して表示します（`bin/find-label.mjs`）。節の内容ではなく役割を名前にしていて、AI の書いた文書によく出るためです。内容を言う文（「書き終えたら、次の問いに答えてみる」「障害はジャンルに合わせて選ぶ」）にします。「使うとき」「迷う場合」のような条件の見出しと、「使い方」「考え方」のような定着した語には表示しません
  - 見出しに数だけを書き、何が N つかを言っていない箇所（「6 つを順に決める」）も、同じスクリプトで検出して表示します。見出しは単独で読まれるので、本文と違って前の文から補えないためです。「次の 3 つを守る」のように、直前の「の」で何の数かを言っていれば表示しません
  - 取得・算出などを口語の動詞で書いた箇所（「割合を出した」「本文を取らない」「ロックを取って」「データから作りました」「作品が混ざる」）も、形態素解析で検出して「算出する」「取得する」「作成する」「含まれる」を示します（`bin/find-colloquial.mjs`）。動詞を基本形で見るので、辞書では検出できない活用した形（「取った」「取らない」）も検出します。「キーを作る」「警告を出す」「責任を取る」のような正しい文に警告を表示しないように、動詞と同じ節に、表で指定した名詞（割合・データ・ロックなど）があるときだけ表示します
  - 意味の広い英語の動詞を日本語の広い動詞に直訳した箇所（「ロックを取って」「設定を変えたら」「関数を呼んで」）も、日本語版 Wikipedia での件数を比べて検出し、定着した動詞（「取得する」「変更する」「呼び出す」）を示します（`bin/find-confusion.mjs`）。手元でコーパスの DB を作成したときだけ動作します（[コーパスの DB を作成する](#コーパスの-db-を作成する)）
  - 書き言葉の文書なら漢語で書く所を、和語で書いた箇所（「方針を決めた」「原因を調べる」「障害が起きる」「たとえば」）も、形態素解析で検出して「決定する」「調査する」「発生する」「例えば」を示します（`bin/find-wago.mjs`）。語の表は `wago.md` にあり、AI の返答の記録と情報通信白書・Ruby のリファレンスマニュアルで、和語を使った割合を比べて選びました。返答では自然な語も多いので、返答を止めるフックには入れていません
  - 責任を避ける書き方も検出します。定型の言い回しは辞書で、語の組み合わせや文書の形で現れるものは `bin/find-avoidance.mjs` で検出します
    - 根拠の無い判定: 「要件を満たした」「対応済み」
    - 確認する人を書かない: 「確認していない」「未確認」
    - 読む人に作業を渡す: 「ここからはあなたの作業です」
    - 指示のせいにする: 「指示どおり」
    - 自分の意図で、相手の受け取り方を否定する: 「嫌がらせではない」
    - 結論が出ているのに選ばせる: 「作りますか？」
    - 全部出す: 「全部」「すべて」が「出す」「並べる」に係る文（「リポジトリを全部出した」）
    - 標準であることを理由にする: 「標準的なやり方なので」
    - 確認していない見込みを根拠にする: 「はず」で終わる文
    - 確認した範囲より広く判定する: 「確認したので、要件は満たしています」
    - 全部並べる: 項目が 10 個以上の箇条書き
  - 確認せずに言い切る書き方（「トークンの期限は 366 日です」）は、言い回しに表れないので検出できません

指摘するだけで、自動では修正しません（`--fix` には対応していません）。修正するのは書き手です。

語彙と書き方のチェックの後に、ローカル LLM（Ollama）に文書を読ませるモードもあります（`--llm`）。主語のねじれや、1 つの文に多すぎる情報のような、ルールでは検出しにくい問題を指摘させます。詳しくは [llm.md](llm.md) を見てください。

## 使い方

利用する側のリポジトリの `package.json` で、aitext-check を devDependencies に追加し、npm scripts から呼び出します。

```jsonc
// package.json
"devDependencies": {
  "aitext-check": "github:zero-platform-lab/aitext-check"
},
"scripts": {
  "lint:ja": "aitext-check",
  "lint:ja:prose": "aitext-check --prose",
  "lint:ja:warn": "aitext-check --warn"
}
```

```sh
aitext-check                         # 語彙（リポジトリの .md すべて）
aitext-check docs README.md          # 語彙（対象を指定する）
aitext-check --prose                 # 書き方
aitext-check --warn                  # 気をつける語句
printf '%s' "$文" | aitext-check --prose -   # 標準入力から読み込む
printf '%s' "$返答" | aitext-check --warn --reply -   # AI の返答を読む。「」の中は読まない
aitext-check --llm docs/spec.md      # ローカル LLM で読む（対象は必ず指定する）
aitext-check --llm --tree --fast docs/spec.md   # 段落ごとにロジックツリーに分解させ、不要な文と重複した文を出す（llm.md）
```

`--reply` は、AI の返答を Claude Code のフックなどで確かめるときに使います。返答では、検出する語そのもの（「未確認」）を「」で引いて説明することが多いので、「」の中を読みません。文書では「」の中にも直すべき文が入るので、文書には使いません。

`--reply` のときは、番号を振らずに 2 つ以上の質問をしている箇所にも warning を表示します（`bin/find-questions.mjs`）。返答を確認する Claude Code のフックは、責任を避ける書き方、動詞を名詞にした語、番号の無い質問、比喩の語（`words.md` の「返答でも止める比喩の語」）、取得・算出などを口語の動詞で書いた箇所の警告で返答を止めます。番号があれば、読む人は「1 はこう、2 はこう」と番号で回答できます。

対象を省略すると、リポジトリの `.md` ファイルすべてをチェックします。

- git のリポジトリの中: git が管理しているファイル（`.gitignore` で除外したファイルは含まない）
- それ以外: カレントディレクトリより下のファイル（`node_modules` と、`.` で始まるディレクトリは除く）

チェックから外すファイルは、利用する側のリポジトリの `.textlintignore` に書きます。書き方のチェックだけから外すファイルは、`.textlintignore.prose` に書きます。

### プロジェクト固有の語句

製品名の表記のように、このパッケージの辞書に入れられない語句は、利用する側のリポジトリに prh の形式で置きます。同梱の辞書に追加して読み込みます。

| ファイル | 足す先 | 重大度 |
|---|---|---|
| `aitext-words.yml` | 語彙 (`aitext-check`) | error |
| `aitext-words.warn.yml` | 気をつける語句 (`aitext-check --warn`) | warning |

```yaml
# aitext-words.warn.yml
version: 1
rules:
  - expected: Entra ID (旧称を指す文脈か、外部資料の引用でなければ Entra ID)
    pattern: Azure AD
    severity: warning
```

書き方のチェック (`--prose`) は語句の辞書を使わないので、足す先はありません。

## コーパスの DB を作成する

`bin/find-confusion.mjs` は、書いた「名詞＋助詞＋動詞」の件数を、同じ名詞と助詞の定着した動詞の件数と比べます。比べる動詞の組は `corpus/confusion.md` の表にあり、件数は日本語版 Wikipedia から集計します。件数の DB はリポジトリに入れないので、使う人が手元で作成します。DB が無いときは、この点検だけを省略します。

DB を作成するには、Node 22.13 以降（`node:sqlite` を使うため）、`bzcat`、ディスクの空き 10 GB ほど（ダンプの 4.7 GB と、取り出した本文の 4 GB）が要ります。

```sh
curl -LO https://dumps.wikimedia.org/jawiki/latest/jawiki-latest-pages-articles.xml.bz2
node corpus/build.mjs jawiki-latest-pages-articles.xml.bz2
```

DB は `~/.cache/aitext-check/corpus.db` に保存します。別の場所に置くときは、環境変数 `AITEXT_CORPUS_DB` で指定します。8 コアの機械では、記事の地の文の取り出しに約 13 分、件数の集計に約 18 分かかりました。`corpus/confusion.md` の表を直したら、DB を作成し直します。

Wikipedia の本文は CC BY-SA 4.0 と GFDL で公開されています。DB に入るのは組の件数だけです。このリポジトリは、DB も取り出した本文も配布しません。

## 辞書に語句を追加する

語句の一覧は、`words.md` の表にだけあります。表に 1 行追加してから、辞書を作り直します。`prh-*.yml` は手で編集しません。

```sh
node build-prh.mjs           # 辞書を作り直す
node build-prh.mjs --check   # 辞書が words.md と一致しているかだけを確かめる
```

文体を指摘する行（`words.md` の「文体を指摘する行」）を修正したときは、試験も実行します。見落としていないこと、誤検出していないこと、「ではなく」を集計した結果が合うことを確認します。

```sh
npm run test:style
```

## ファイル構成

- `words.md`: 語句の一覧（辞書の元データ）
- `prh-error.yml`、`prh-warn.yml`: `words.md` から作った prh の辞書
- `.textlintrc.yml`、`.textlintrc.prose.yml`、`.textlintrc.warn.yml`: textlint の設定
- `build-prh.mjs`: `words.md` から辞書を作成するスクリプト
- `bin/cli.mjs`: 同梱の設定で textlint を実行する CLI
- `bin/count-dewanaku.mjs`: 「ではなく」を節ごとに集計するスクリプト（`--warn` が textlint の後に実行する）
- `bin/count-taigen.mjs`: 体言止めの文を、形態素解析で節ごとに集計するスクリプト（`--warn` が textlint の後に実行する）
- `bin/count-paragraph.mjs`: 段落ごとに文を集計するスクリプト（`--warn` が textlint の後に実行する）
- `bin/find-nominal.mjs`: 動詞を名詞として使った箇所を、形態素解析で検出するスクリプト（`--warn` が textlint の後に実行する）
- `bin/find-wago.mjs`、`wago.md`: 書き言葉の漢語にできる和語を、形態素解析で検出するスクリプトと、その語の表（`--warn` が textlint の後に実行する）
- `bin/find-avoidance.mjs`: 責任を避ける書き方を、文の組み立てと箇条書きの長さから検出するスクリプト（`--warn` が textlint の後に実行する）
- `bin/find-colloquial.mjs`: 取得・算出などを口語の動詞で書いた箇所を、形態素解析で検出するスクリプト（`--warn` が textlint の後に実行する）
- `bin/find-questions.mjs`: 返答の中で、番号を振らずに 2 つ以上の質問をしている箇所を検出するスクリプト（`--warn --reply` が textlint の後に実行する）
- `test/`: 気をつける語句のうち文体を指摘する行の試験（`npm run test:style`）
- `bin/llm.mjs`、`llm/prompt.md`: ローカル LLM で読むモードと、その指示文
- `llm.md`: ローカル LLM で読むモードの使い方と、指示の決め方の根拠

ルールの本体（textlint、prh、ja-technical-writing）は npm の依存パッケージです。このリポジトリには含めていません。
